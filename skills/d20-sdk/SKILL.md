Public protocol reference: `de5f82eb9fc749c80e83270f57cde9908ddcf1f3`. Match the installed SDK provenance and the deployed implementation history before use; each deployment manifest records the source its implementations were deployed and upgraded from.

Install with `npm install @d20dao/vrf-sdk` (0.4.0 or newer). Use Node >= 22.13 and Solidity 0.8.28. Read the packaged README, AGENTS.md, exported declarations and PROTOCOL-PROVENANCE.json, and match them to the selected deployment's proxy addresses and implementation history. The package is ESM only: bundle it for browsers, or import only `@d20dao/vrf-sdk/abi` when you need just the ABIs. Installing the package does not onboard a consumer; the public service needs no registration. For agents that pay per call over HTTP, see **d20-agent-api**.

Fees are `max(minFee, feeMultiplier × baseFee × (fulfillGasOverhead + callbackGasLimit))`, and `pricing()` returns the live parameters. `ID20VRF.quoteFee(callbackGasLimit)` is exact only inside the requesting transaction. Off-chain, use `quoteRequestFee(provider, coordinator, callbackGasLimit, { bufferBps })`: it reads the latest header's `baseFeePerGas`, calls `quoteFeeAt` and returns both the exact quote for that header and the buffered amount to send. Never quote with `quoteFee` through `eth_call`, which commonly sees a zero base fee. Excess becomes refund credit of the refund address (`withdrawRefundCredit`); underpayment reverts with `IncorrectFee(expected, actual)`.

Consumer imports use `@d20dao/vrf-sdk/contracts/D20VRFConsumer.sol`, `interfaces/ID20VRF.sol`, `libraries/D20VRFRequests.sol` and `libraries/RandomnessMapping.sol` with compiler 0.8.28; they import only each other, so a consumer needs no OpenZeppelin installation. The `D20VRFRequests` helpers pay `quoteFee` from the calling contract's balance. The packaged example consumers are illustrations, not the product scope.

Root exports include the mapping helpers (`builtins`, `mapRandomness`, `hashMapping`, `validateMapping`), `encodeEvidencePacket`/`decodeEvidencePacket`, `replayCoordinator`, VRF and attestation helpers, and the data-template helpers `encodeDataTemplate`, `decodeDataTemplate`, `matchesDataTemplate`, `isValidDataTemplate` and `validateDataTemplate`. `/epoch` exposes epoch operations, including `MAX_ATTESTATION_AGE` (240 seconds), `BUILTIN_EPOCH_RECIPES`, `INITIAL_EPOCH_RECIPES`, `readEpochRecipes` and `resolveEpochCatalog`. `/abi` exports `coordinatorAbi` and `epochEntropyAbi` (JSON names `D20VRFCoordinator.json` and `EpochEntropy.json`): `coordinatorAbi` carries `quoteFee`, `quoteFeeAt`, `pricing`, `requestFeePaid`, `requestRefundBps`, `withdrawRefundCredit`, `fulfillRandomnessBatch` and the recovery functions, and `epochEntropyAbi` carries `registerRecipe`, `getRecipe`, `recipeRequest`, `recipeCount`, `scheduleCatalog`, `catalogAt`, `sourceCountAt`, `setBackupCommitter`, `isBackupCommitter` and `isAuthorizedCommitter`.

Epoch sources live in an append-only on-chain recipe registry. Six recipes are registered built in; the owner adds more with `registerRecipe` and puts registered ids into a future epoch's catalog with `scheduleCatalog`, so a new source needs no contract upgrade and no SDK release. An `EpochCatalog` carries its signers, optional recipe ids and an optional `recipeBook` of definitions; `resolveEpochCatalog` builds one from `catalogAt`, and ids missing from the book resolve to `BUILTIN_EPOCH_RECIPES`. Read any other registered recipe with `readEpochRecipes`.

`RequestContext` binds requestBlock and targetBlock. Replay `configuration` uses the initialized `initialFeeRecipient` and `initialMinFee`, not the mutable payout address or live pricing; `configuration.catalogHash` is the initial catalog bound into protocolConfigurationHash, while `epoch.catalog` must be the catalog in force for the request's epoch (`catalogAt`, through `resolveEpochCatalog`, or the `CatalogScheduled` history). Proof evidence is 416 bytes and single `fulfillRandomness` calldata 452 bytes; take evidence from `FulfillmentEvidence` logs, never from calldata, since batch calldata differs. Epoch evidence carries the full signed packet. Decoding and mapping are not proof verification.

The keeper prepares local snapshots for 200-block epochs, and idle preparation causes no publication transaction. Live paid demand escrows the quoted fee, triggers publication and resolves `targetBlock = max(requestBlock, commitBlock + 1)`; the original 60-second deadline stays fixed. `fulfillRandomnessBatch(ids, proofs)` fulfills up to 16 requests with the same per-request events and callbacks as `fulfillRandomness`; skipped members emit `FulfillmentSkipped(requestId, reason)`.
